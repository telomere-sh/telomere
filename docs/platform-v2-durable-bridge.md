# Default-off Platform v2 durable-run bridge

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

`PlatformV2AdmissionJournal` and the optional third `PlatformHostExecutor` constructor argument form a pre-admission gate for **one-shot paid CPU runs**. The executor first saves the controller-signed HostKit lease. When the gate is enabled, it then verifies the canonical `RunOpened` transaction and current registered host key, checks the original quote EOA signature, signs a lease-specific EIP-712 controller delegation, stores it in a separately initialized table, and reads it back **before** calling HostKit `admit`. It rechecks current run, leash, host and expiry state immediately before returning the certificate; a stopped run or killed leash fails closed. A certificate-storage or authority failure prevents host admission and removes the exact unadmitted lease row. Paid sessions fail closed when the gate is enabled: the v2 core does not bind their separate command-event history. The default constructor omits the gate and retains v1 behavior, including paid sessions. The table is not part of the default migration or live configuration, and no production process mounts this gate.

`src/receipts/platform-v2-durable.ts` reads the actual `platform_runs` and `platform_host_leases` journals for a terminal one-shot paid CPU run. It checks the original owner, signed quote workload, complete **persisted** signed HostKit lease/tick/ACK sequence, cleanup flag, CPU result and conservative financial outcome before invoking the isolated v2 evidence-core verifier. It refuses NEAR inference, paid sessions, synthetic zero runs and CPU runs with no signed HostKit lease. It returns a deterministic redacted v2 candidate and the existing settlement's version relationship.

The live `PlatformRuntimeService.persistOutcome` still creates a v1 receipt. For such a run the bridge returns `receiptVersion: "v1-existing"`; `requirePlatformV2DurableHash` rejects it. Neither this adapter nor the v2 journal rewrites the original financial outcome. A different output salt changes the v2 hash, so a future v2 producer must persist the salt before any settlement intent and reuse it after restart.

`confirmPlatformV2DurableSettlement` is a post-settlement guard for a locally committed v2 hash. It requires the reviewed bridge scope, a published financial-root proof from `PlatformReceiptService`, and the canonical `RunSettled` event, onchain run state and accounting from `PlatformBridge.confirmedSettlement`. It reports `onchainReceiptVerified: true` only after those checks. It continues to report `independentlyPublished: false` and `historicalAuthoritySource: "caller-supplied"`; it does not turn a locally supplied signer snapshot or private journal into an independent public receipt.

`tests/platform-v2-durable-bridge.test.ts` uses disposable Anvil contracts and a real HostKit signed local process fixture. HostKit's first `admit` observes the already persisted delegation. Wrong host/controller keys, a modified quote and a stale admission transaction fail before host admission; a forced certificate-store failure stops a second host admission. The paid-session fixture also checks that session admission is refused by the optional v2 journal, while v1 sessions still run, and that cancellation during an opt-in authority check removes the unadmitted lease without contacting HostKit. The test then derives the full v2 package from durable HostKit rows, proves that the real v1 settlement cannot be relabeled v2, and holds the normal v1 financial record **inside the test only** to exercise an isolated v2 local settlement/root path. The v2 hash is committed to the local financial root and settled on Anvil; a subsequent canonical check passes. Reordered persisted ticks and a reorg that removes the financial root fail closed. This is not a production switch and does not publish the redacted core to independent immutable storage.

Before enabling v2 for public paid runs, the runtime still needs a producer that durably stores a random output salt before any settlement intent, two independent immutable evidence copies indexed by digest, archive-backed historical signer/host/quote authority including canonical `openRun` calldata and confirmation depth, a public digest-based retrieval route, and recovery at every publication boundary. The [mounted verification API](platform-v2-public-api.md) accepts a caller-presented core and does not supply those producer or retrieval steps. Existing Cyst S3 adapters are private ciphertext stores; their conditional PUT and readback rules can inform a separate public evidence adapter, but they do not establish retention lock or public independent retrieval. The new gate establishes local issue/persist/admit ordering, but its database `createdAt` is private operational audit data. The EOA certificate has no independently verifiable issuance timestamp; a public verifier cannot yet prove historical authorization during execution. A chain stop, leash kill or reorg can still land between the final RPC read and HostKit admission, so the normal run monitor must stop the host and reconcile the original lease. The wallet-funded Base deployment remains a separate external acceptance gate.
