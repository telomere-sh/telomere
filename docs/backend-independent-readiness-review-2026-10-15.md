## Supplier review findings

**No actionable authority, lost-liability or durability regression was found in the reviewed supplier changes.** This is a scoped code review, not an independent security audit.

The relevant financial transitions have these concrete properties:

- `private-journal.ts:137` refuses fresh initialization when either original file or marker survives. Normal reads and transactions never create an empty replacement. A missing marker or data file therefore cannot silently clear a retained liability.
- `private-journal.ts:111` uses an exclusive writer identity. Replacement of the lock is checked before commit and before removal. A mutation or durability failure after uncertainty is declared leaves the lock for explicit recovery; age or PID does not grant new authority.
- `private-journal.ts:158` checks the original marker generation and exact original file before atomic replacement, then verifies the committed bytes after mandatory POSIX directory synchronization. Validation failure before a filesystem mutation preserves original bytes.
- `shared-reserve.ts:31` binds the original peer paths and exact ceiling. Its retained state pins both peer generations; `shared-reserve.ts:47` refuses a newly initialized peer pair against the old shared state.
- `shared-reserve.ts:59` only releases a failed local callback when both peers and generations can still be read unchanged. Changed or unreadable outcomes retain the shared lock. The existing callback is a local journal mutation, not a supplier POST.
- Existing Akash pending states are persisted before an external single-attempt submission; canceled-unsubmitted is the only Akash state releasing its projection. Closed, unsettled and quarantined records remain included in the held reserve. Nosana terminal observations do not release their original reserve.

Two limitations are intentional and must remain visible. `read()` at `private-journal.ts:108` is diagnostic even when a writer lock survives; it does not authorize another mutation or establish final settlement. Static local markers do not authenticate the freshness of a valid older journal restored by an operator. Valid rollback, or deletion of all local anchors, still needs independent original supplier inventory/accounting and an explicitly reviewed recovery. Neither limitation is a newly introduced spending path.

The changes add no production supplier mount or spending authority. They do not complete deployment delivery, in-Cell supplier heartbeat metering, final provider debts/refunds, the 2% adapter-revenue reserve or network-token conversion/rebalancing. [The supplier execution assessment](supplier-execution-readiness-2026-10-15.md) remains applicable. No additional M6 execution percentage is awarded for storage hardening.
