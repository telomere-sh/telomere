# Nosana read-only supplier admission (M6)

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

This slice can adopt and reconcile an **already-running** Nosana GPU job on an explicitly approved node. It cannot create, extend, stop, or pay for a job. The reader calls only `GET https://api.nosana.com/jobs/{address}` and `GET https://api.nosana.com/api/markets/{address}` on a fixed origin. Both exact gateway URLs returned HTTP 200 with `application/json` and matching `address` on 12 October 2026, for the public job and market recorded in the test fixture. The official [Nosana SDK job route](https://github.com/nosana-ci/nosana-kit/blob/main/packages/api/src/routes/jobs/index.ts) uses the indexer's `/jobs/{address}` path; its [market route](https://github.com/nosana-ci/nosana-kit/blob/main/packages/api/src/routes/markets/index.ts) uses the host-manager's `/markets/{id}` path, exposed through the public gateway as `/api/markets/{id}`. No wallet, API key, public transaction, or paid job was used for the validation.

The [Nosana Kit Jobs Program](https://github.com/nosana-ci/nosana-kit/blob/main/packages/kit/README.md) defines job states `QUEUED=0`, `RUNNING=1`, `COMPLETED=2`, and `STOPPED=3`, a direct-node job assignment that requires a signed transaction, and a price in the smallest NOS unit per second. [Nosana token documentation](https://learn.nosana.com/programs/token.html) states six token decimals. The official [Nosana API Jobs guide](https://learn.nosana.com/api/jobs.html) distinguishes indexed job data from authenticated node job data. Reading `/jobs/{address}/node/results` can advance a finished job, so this adapter does not call it.

`NosanaSupplierService.admit` requires an authoritative Telomere GPU run callback with an exact owner, run ID, Solana payer, market, IPFS workload CID, duration, USDC ceiling, canonical escrow opening time, and expiry cut off by the run, Leash, or stop. The expiry must not extend beyond the approved duration. It then reads the job and market, requiring state `RUNNING`, an allowlisted node and market, premium market type, exact payer/CID/market, a bounded price and timeout, and a job interval wholly inside that funded run window. A job that started before the onchain reservation or could end after its expiry is refused. Queued jobs are rejected: a queued job may have no assigned node yet, so an allowlist check at that point would not constrain its eventual host. This service accepts no public placement inputs for the payer or image.

The trusted treasury callback supplies available NOS base units and a **direct NOS→USDC** conversion observation, timestamped no more than 60 seconds ago. No USD or USDC parity assumption is used. Reserve = `price_base_units_per_second × job_timeout_seconds × (1 + buffer_bps/10000)`, with buffer at most 3%, converted using `usdcMicrosPerMillionNosBaseUnits`. Both the approved run's USDC ceiling (maximum 250 USDC) and a configured total USDC exposure cap must cover this quote. This is a local admission projection, not a chain-enforced spending limit; NOS price movement, API lag, and already-incurred external spend remain operator risks.

The JSON `price` is accepted only as a positive safe integer, so conversion to `BigInt` cannot silently round a larger base-unit value. The regression test rejects `2^53` from the HTTP reader. An API response that changes price representation must be handled with an explicitly revised schema before admission is enabled.

The local journal saves the exact job/node/payer/market/CID/price/timeout/start identity, reserve, quote provenance, and observation state. Exclusive locking and atomic rename prevent duplicate local reservations for an idempotency key, Telomere run, or Nosana job. Nosana admission also requires the [shared Akash/Nosana reserve](supplier-shared-reserve.md), which serializes both journals and checks one combined projected USDC ceiling. A crash-held lock fails closed until the operator confirms the previous writer has stopped. Reconciliation moves a completed or stopped job to `closed_unsettled` only when its end timestamp is present, no later than the local observation, and no later than the original job timeout; it retains the entire reserve until independent final accounting exists. A changed node, price, workload, time bound, market type, or status regression causes sticky quarantine. Indexer failure leaves the old observation unchanged and never produces a billable tick.

Every public reservation reports `jobPostingEnabled=false`, `meterEligible=false`, `billableSeconds=0`, and `refundConfirmed=false`. An indexed `RUNNING` state does not prove in-cell heartbeat, Telomere meter continuity, final NOS spend, or a valid refund. The [Nosana `jobs:read` scope](https://learn.nosana.com/api/jobs.html) can later support authenticated node observations, but receipt signing and independent provider evidence are still required.

Validation: `tests/supplier-nosana.test.ts` exercises identity pinning, direct NOS→USDC quote, restart/idempotency, allowlists, the funded time window, stale oracle, budget/inventory caps, closed-job retention, sticky quarantine, remote failure, exact GET-only gateway paths, selected fields captured from actual public JSON responses, and unsafe price rejection. Remaining work: wire the approved-run and treasury callbacks to authoritative Telomere state, move the journal into the controller's PostgreSQL transaction boundary, verify finalized Solana program accounts and authenticated node heartbeat, and perform a funded acceptance under an explicit release gate. Both current Telomere escrow paths cap a run at 120 seconds, while the GPU callback and fixture here are component-only; no real GPU run can currently authorize a longer Nosana job. This slice does not by itself make the Nosana adapter launch-ready.
