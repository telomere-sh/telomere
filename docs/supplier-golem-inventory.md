# Golem indexed provider inventory (M6 groundwork)

`GolemStatsReader` reads the current Stats frontend's [provider endpoint and response shape](https://github.com/golemfactory/golem-stats-frontend/blob/main/pages/network/provider/%5Bnode_id%5D.tsx): `GET https://api.stats.golem.network/v2/provider/node/{yagna_id}`. The older [published API guide](https://github.com/golemfactory/stats-api-docs/blob/master/v1-api-endpoints/provider-specific.md) still describes v1, so it is not used as the response contract here. It accepts only explicit, validated Yagna node IDs and makes no network write. An operator or an independently authenticated allowlist must supply those IDs. The reader does not enumerate or approve the public marketplace.

The returned observation contains the indexed node identity, selected `vm` or `vm-nvidia` runtime, CPU cores and threads, memory, storage, reported online flag, and the indexer's `updated_at` time. NVIDIA inventory additionally requires a GPU model. The reader rejects a runtime whose `properties` are absent or null: [the Stats frontend treats this as no recent offer scan](https://github.com/golemfactory/golem-stats-frontend/blob/main/pages/network/provider/%5Bnode_id%5D.tsx). `recentlyObserved` is true only when the index timestamp is no more than five minutes old and no later than the local clock. The `onlineReported` and `recentlyObserved` fields are **not** proof that an offer is open, capacity is available, the node is approved, or a Telomere run can execute there. The Golem [requestor flow](https://docs.golem.network/docs/creators/common/requestor-provider-interaction) requires Yagna, a demand, a matching offer, an agreement, and a separate payment allocation. This slice has none of those operations, no wallet, no reservation or payment adapter, and no metering integration.

The fixed endpoint, GET-only method, disabled redirects, five-second timeout, one-megabyte response cap, exact response identity, bounded batch of 64 IDs and four concurrent requests limit the read boundary. An index response with incomplete resource fields fails closed. It never accepts a caller URL or uses provider-supplied strings as a URL.

`tests/supplier-golem-stats.test.ts` exercises an offline fixture matching the current frontend's response shape, including identity, stale and absent runtime properties, freshness, malformed data, content type and response-size checks. On 13 October 2026, `api.stats.golem.network` returned no DNS answer from this workspace, so **live API acceptance is unverified**. The [Golem reputation filter](https://docs.golem.network/docs/reputation/finding-the-best-providers) also timed out from this host during this check. Before using Golem for M6 release, confirm an operating official API or Yagna market source, pre-approve concrete node IDs, and test offer, execution, authenticated runtime evidence, GLM inventory and settlement against real accounts. No Golem activity is billable in Telomere through this module.
