# Mandatory backend functional reassessment, 14 October 2026

Provisional central assessment: **approximately 73%**, engineering range **68.9–77.0%**, excluding optional arbitrary GPU Cells (M4). Approximately **27.1% remains** at the unrounded midpoint. This measures the original mandatory backend functions, not public launch readiness, elapsed schedule or the fraction of passing tests. The combined final full regression and exact-source release snapshot are separate evidence; this reassessment does not pre-announce their result.

The denominator remains nine equally weighted original milestones, M1–M3 and M5–M10. Source scope is the supplied PDFs extracted into `work/telomere/backend.txt` and `work/telomere/overview.txt`; the active settlement target is Base/native USDC. Managed verifiable model inference remains required. Removing GPU Cells does not remove external-supplier operation, sealed CPU key release, ordinary CPU isolation or independent Cyst recovery.

## Evidence boundaries

- [CPU v2 issuance acceptance](platform-v2-acceptance-2026-10-14.md) demonstrates original execution, signed evidence, failed publication/restart, actual financial commitment and public retrieval on local Anvil/process/storage fixtures. Two configured copies do not establish independent durable regions.
- [Paid lifecycle v2](paid-agent-lifecycle-v2.md) describes actual full/lean/sleep/wake/torpor/kill behavior and the Linux retry with measured NanoCpu settings. Its initial warmup failed; the retry waits for a retained positive signed billing interval and keeps the financial assertions strict. Exact final release-source acceptance is a separate gate.
- [Mounted economics acceptance](platform-economics-runtime-validation-2026-10-14.json) uses actual EOA and canonical Vault payments, inside/outside-five-percent host selection and positive canonical settlements after the owner's holdings fall to zero. It uses financial domain 2 and CPU receipt v1; that test alone does not prove Vault v2 issuance.
- [Economics mechanism and historical evidence](tlmr-economics-v2.md) has a focused cohort including actual token movement, time-weighted rewards, real local supply burn, exact unsigned preparation/reconciliation, original v2 compatibility and reviewed nested Vault opening. The CPU work producer is exercised against an actually published signed v2 completion. Non-compute observations remain approved publisher testimony rather than independent physical measurements.
- [Framework acceptance](framework-starters-validation-2026-10-14.json) runs ElizaOS/Automaton handlers and CLIs over actual authenticated HTTP, one real Vault-paid CPU task, a separately held agent wallet and an encrypted journal. It does not run a complete production LLM agent loop. Existing LangGraph acceptance remains separately recorded.

No local-EVM token movement is a funded Base transaction. No local signature fixture proves hardware TDX confinement, independent storage durability, external supply availability or an approved economic price.

## Remaining implementation, beyond deployment tests

1. **External supply:** total-liability-bounded lease creation with a real supplier meter and in-Cell heartbeat; final cancellation/settlement accounting; Golem/requestor execution; network-token working inventory, conservative conversion/rebalancing and finalized top-up crediting. The current Akash signed path correctly refuses paid submission because its lifetime spend limit is not enforced atomically.
2. **Sealed CPU lifecycle:** a reviewed operational DCAP/TDX appraisal source, measured CPU workload admission and challenge-bound key release through actual sealed restore. A model inference API cannot replace that agent runtime/key-recipient path.
3. **Persistence and life:** application-independent filesystem/state packaging and larger paid restore; the original default checkpoint/trigger behavior connected to all execution modes; durable automatic renewal/replacement policy beyond separately preapproved 120-second reservations; explicit expired/lost-source recovery without relying on a surviving host's cleanup report. Existing local 2-GiB storage-format acceptance is not a 2-GiB paid Cell restore under 20 seconds.
4. **Payment and treasury breadth:** complete original x402 exact/upto→Cell/Leash/Selection integration, Base Account spend-permission consumption and finalized Solana Pay→Base credit. Existing native USDC Vault income and bounded balance-paid CPU paths do not imply those separate rails are complete.
5. **Replacement and prices:** a mounted owner-approved multi-step cross-lane replanner that creates and reconciles a safe replacement without counting pending refunds twice; complete per-class/per-lane market data where actual admitted supply exists. Current proposals and restricted CPU receipt windows are deliberately narrower.
6. **Economic operations:** production collectors/publication for accepted probe, verifier and storage observations; an explicitly approved complete work inventory/weight policy; an operator with an original durable wallet journal for weekly root posting and signed buy/burn; deployment-time supply/allocation, quote-price and DEX/liquidity review. The new mechanisms execute locally and the preparation helpers do not silently acquire signing authority.
7. **Governance and public operation:** prescribed fault classification/penalty automation, reviewed Safe/timelock/bootstrap roles, canonical Base identity/reputation targets, independent storage-failure-domain recovery, source verification, audits and operator recovery acceptance. Some of these require infrastructure or independent reviewers as well as code.

Managed model inference remains a separate required live acceptance: current strict rejection of the expired policy/Gateway appraisal is preserved. No paid request is credited merely because Enclave previously had an inference API key or GPU appraisal.

Even if the other seven mandatory milestones reached 100%, the unchanged M6 upper bound of 20 and M7 upper bound of 35 produce **(700 + 20 + 35) / 9 = 83.9%**. A 90% statement therefore still requires meaningful supplier and sealed-CPU completion; more local tests or omitting GPU Cells cannot remove that limit.
