# Default-off HostKit v2 admission envelope

`ArchiveHostV2AdmissionAuthority` is a host-configured read-only verifier. It receives reviewed Platform deployment pins and an archive-capable RPC client at construction; a request cannot choose either. Before the first HostKit reservation it validates the exact controller-signed lease, quote and quote EOA signature, lease-specific EOA delegation, direct canonical `openRun` transaction, opening-block code and host authority, and current open run, leash and registered CPU host state. Its current-block check also pins the payment asset, proxy implementation and facet when applicable, escrow, receipt root, registry, fee router, their relationships and financial limits. The HostKit route `/v2/leases` is mounted only when this authority is explicitly passed to `HostKitAgent`. No normal production configuration passes it. A v2-bound host advertises v1 capacity as unavailable and rejects every new `/v1/leases` admission before reservation or dispatch. The v1 control endpoint still serves status and stop for the original v2 lease. Startup refuses any v1 run row under the permanent v2 binding after orphan cleanup. Ordinary v1-only hosts retain their existing admission behavior.

The separate v2 route rejects a run ID already admitted through v1. For a new run it signs a domain-separated host admission receipt over the exact envelope hash, delegation hash, quote hash, signed lease hash, meter lease hash, opening transaction and block hash, host/controller keys and run scope. The original lease and signed receipt are inserted in the same host journal row. HostKit reads that row back and verifies its host signature **before** calling `runtime.start`; a failed write or readback fences the host and starts no cell. Exact request retries return the original receipt without redispatch. The host's local execution budget is additionally capped by the strict opening-time v2 cutoff.

Plain v1 startup atomically claims or verifies its own permanent `cpu1` binding before runtime initialization and orphan cleanup. Its scope fixes the host key, controller key and isolation. It may adopt up to 4096 legacy plain one-shot run rows only after verifying each row's signed controller lease, host key, run identifier, owner and lease hash. It refuses a different binding or any shared-claim, hosted-session, paid-session, preemption or v2-admission history. The shared and v2 startup paths reject the plain binding, including when both modes initialize concurrently. One `HostKitAgent` owns a journal object from initialization through cleanup in every mode; a later agent can initialize after the first closes. A same-scope plain restart retains ordinary v1 admission behavior.

The receipt is a signed statement by the registered HostKit host. It does not independently timestamp the EOA delegation or prove that an untrusted physical host never ran an earlier workload. [Explicitly enabled CPU v2 issuance](platform-v2-issuance.md) now sends the exact envelope through this route, journals the response before ticks, commits the signed admission in its public core, and checks its opening reference against canonical history. Legacy cores without an admission retain their original hash and expose `hostAdmissionVerified: false`; the default runtime remains v1. Independent historical pre-admission proof and live rollout are still required. At startup the opt-in mode atomically claims a permanent `cpu1` row in `host_binding` with a deterministic v2-only scope. A shared `HostAdmissionCoordinator` rejects that scope, while v2 rejects any other binding or shared claim, hosted session or paid-session history. V2 checks its exact binding before and after the archive RPC and in the transaction that inserts the run. The route cannot be composed with paid-session routes. One-shot capacity verifies this binding and can report availability; session capacity stays unavailable.

`tests/host-v2-admission.test.ts` exercises the opt-in route with a real local Anvil opening and a HostKit process fixture. It verifies that the signed receipt is already durable when process dispatch begins, that malformed or mismatched EOA delegation is rejected before dispatch, that an identical retry does not rerun the task, that neither v1 nor v2 can upgrade or reinterpret a run admitted in the other mode, that current payment asset code drift is rejected even when the opening archive remains valid, and that a normal HostKit agent does not expose the route. It rejects paid-session route composition and shared binding, claim or paid-session rows at startup, and verifies that a real shared coordinator refuses the v2-bound CPU journal. It also closes and reopens the disk-backed journal with the same host key and CPU binding, checks the exact receipt and replay without dispatch, and rejects startup after an on-disk receipt is altered.
