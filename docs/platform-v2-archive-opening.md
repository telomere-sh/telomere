# Platform v2 archive-backed opening authority

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

`readPlatformV2OpeningAuthority` is an isolated, read-only verifier for the original paid CPU run opening. It accepts reviewed `PlatformPins`, the exact `openRun` transaction hash, an archive-capable `viem` public client, and a minimum confirmation depth (12 by default). It fetches the transaction and successful receipt, requires a direct zero-value escrow `openRun` call on the pinned chain with canonical calldata, checks the matching escrow and HostRegistry `RunOpened` logs, and verifies the original EIP-712 quote signature against `quoteSigner()` in the opening block.

All historical contract reads use the canonical opening block hash: the escrow run, HostRegistry host key and operator, contract bytecode, immutable relationships, six-decimal payment asset, and any reviewed USDC implementation/facet pins. The reader recomputes the registered `hostId` from chain ID, registry, operator, and host key. It checks confirmation depth and the block hash before and after those reads. Missing archive state, an altered quote or signature, a wrong host key, changed code or relationships, insufficient depth, or a reorganization fails closed. The companion `verifyPlatformV2OpeningEvidence` calls this reader and then the v2 cryptographic evidence-core verifier, with another canonical block check before returning.

The derived `cutoff` is the **strict v2 opening-time policy bound** `min(openedAt + maxSeconds, acceptedExpiry)`. It is not the contract's general settlement upper bound: the contract can accept a later `endedAt` if the run remains open before its refund deadline. Such a valid chain settlement may be rejected by this conservative v2 verifier, so it is incomplete as a general settlement verifier. A later `requestStop` or `killLeash` can reduce the legitimate end time further. This reader does not prove those later events, the final financial settlement or receipt-root inclusion. It also does not prove independent publication of the evidence core, computation correctness, or that a controller delegation was signed before execution. The wrapper therefore leaves `onchainReceiptVerified` and `independentlyPublished` false. Complete public v2 verification still requires an independently retrievable immutable core and the canonical settlement/root verifier.

The archive RPC and reviewed deployment pins are trust inputs. Block-hash reads and rechecks detect ordinary reorgs and missing historical state; they are not a light-client proof against a Byzantine RPC that fabricates coherent transaction, receipt, block and state responses. For deployment, configure a trusted archive endpoint and independently check the chain and deployment pins. This module has no HTTP mount or paid-chain write path.

The local Anvil regression test opens a 20-second CPU run, sets `endedAt` to 25 seconds after opening, publishes the required financial root, and settles one billable second successfully onchain. Its `endedAt` exceeds the archive reader's strict v2 cutoff. This confirms the deliberate completeness limit with a real contract transaction rather than an assumed contract rule.
