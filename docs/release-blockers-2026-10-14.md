# Revised backend: remaining acceptance, 14 October 2026

Network update, 14 October 2026: the active implementation targets Base and native Circle USDC. Earlier Robinhood/USDG evidence below remains historical and does not prove Base deployment or funded acceptance. See [the current migration record](base-usdc-migration-2026-10-14.md).

This records the remaining work for the Telomere backend, now targeting Base/native USDC after arbitrary GPU Cells became optional. Managed NEAR model inference and M1–M3, M5–M10 remain required. The local engineering estimate is about 72% functional coverage (67.4–75.9%, midpoint 71.7%); it is not a public-release readiness score. Default-off prototypes, fixture attestations and local Anvil settlement are not live acceptance.

## Work that needs external infrastructure or authority

1. **NEAR inference:** approve and pin a current measured-workload policy, independently review the changed workload and canary, obtain a strict current Gateway TCB verdict or approve the reviewed direct route, then accept one bounded Telomere inference completion with verified response binding. The Enclave credential currently proves model-inference access only; the 13 October checks rejected the expired Telomere policy and Cloud Gateway `OutOfDate` verdict. Do not send a paid request while either admission condition fails.
2. **M6 supplier settlement:** obtain an approved Akash account/provider deployment and a lease path that enforces both the selected bid's price and maximum lifetime cost, or an independently reviewed bounded-spend mechanism. Support the selected bid's actual denomination, reconcile token escrow/charges/refunds and token-to-USDC conversion, and verify live heartbeat and final close against a funded admitted Telomere run. The optional chain preflight verifies a complete BidID and unit price but cannot bound the lease's total spend; the local planner now handles the observed fractional `uact` precision exactly, while sampled non-`uact` bids still fail closed. A [direct-chain fixed-deposit feasibility review](akash-self-custody-budget-feasibility.md) found a possible cap on transferable escrow funds, but Akash can record unsettled overdraw, so it is not a strict cap on accrued supplier liability. Signed mode deliberately stops before any paid POST. Local planning and read-only observation do not supply a Cell.
3. **M7 sealed CPU Cell:** provision a real Intel TDX CPU host or CVM and an independent DCAP appraiser with current collateral and approved measurements. Bind its hardware report to the challenge, run, recipient key and expiration before owner-key release; deliver the encrypted packet to the attested recipient and restore a Cyst inside that Cell. The default-unmounted signed-appraisal adapter authenticates an external verdict in fixture tests but is not a hardware verifier by itself. NEAR model-inference attestation cannot stand in for CPU Cell attestation.
4. **Independent recovery and public evidence:** exercise paid handoff after loss of one *physical* host, with checkpoint copies in independently verified S3 regions, then restore the stopped deployment from backup. [Opt-in CPU v2 issuance](platform-v2-issuance.md) now integrates actual HostKit v2 admission, commits the signed admission plus tick/ACK sequence, preserves the original result/salt through restart, verifies two configured publication copies before financial issuance, and settles that hash in local Anvil acceptance. The [mounted bounded API](platform-v2-public-api.md) retrieves and verifies both configured copies as well as caller-presented cores. The reviewed S3 adapter and private configuration gate are implemented. Live exclusive HostKit deployment, independent storage durability/domain acceptance and canonical public Base settlement remain unaccepted. Store identities/domains are operator declarations, so `independentlyPublished` stays false. The delegation's pre-admission signing time is still not independently proven.
5. **Base financial acceptance:** use a funded owner-controlled Base Sepolia wallet only after the preceding paths are ready. Pin native Circle USDC proxy code, its legacy implementation slot/code and chain-specific authorization domain through an archive-capable private RPC; deploy/review canonical contracts; run funded quote, admission, settlement, refund, stop and reorg tests. Confirm limits, monitoring, restore drill, Safe/timelock/guardian controls and the two independent audits required before public funds.

The user chose to test the wallet last. That order does not waive the funded chain acceptance gate. The remaining external dependencies require the corresponding owners or providers; source changes alone cannot make the backend release-ready. If M6 remains at or below 20% and M7 at or below 35%, even perfect scores on the other seven mandatory milestones cap the nine-milestone functional estimate at 83.9%.

The [full CPU paid lifecycle runner](paid-agent-lifecycle-runner.md) has local two-hop/three-reservation continuation and final accounting acceptance. It does not replace longer-lived leases, generic sleep/wake/kill or lean/torpor execution, physical-host-loss recovery or confidential TDX key release. The new v2 producer and admission binding remove local integration gaps; their acceptance is recorded separately and does not automatically rescore the earlier 72% estimate or waive live deployment gates. A 14 October connection attempt to the original private VPS SSH route timed out before authentication; no server files or services were changed and no new Linux acceptance was obtained.
