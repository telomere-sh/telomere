# Compatible native Large Cyst chunk AEAD

The separate production change is commit `c87824f698020aa561ffb9df6d6c6874e4b644ba`, immediately after `7bb69e5`. It adds one bounded chunk helper, changes the two Large Cyst encryption/decryption calls and adds interoperability/security tests. There are no new dependencies or changes to the encrypted format, random 24-byte nonce prefix, AAD, header/manifest HMAC, key wrapping or recovery-key custody.

The helper uses the already pinned `@noble/ciphers` 1.3.0 HChaCha implementation to derive a subkey from the first 16 nonce bytes. It passes that subkey and four zero bytes followed by the final eight nonce bytes to Node's IETF ChaCha20-Poly1305 implementation. The output remains ciphertext followed by the 16-byte tag. The construction and public test vectors follow the [XChaCha draft, sections 2.2.1, 2.3 and Appendix A.1](https://datatracker.ietf.org/doc/html/draft-irtf-cfrg-xchacha-03); the pinned implementation is the [official noble 1.3.0 source](https://github.com/paulmillr/noble-ciphers/blob/1.3.0/src/chacha.ts). This is compatibility with the existing format, with no claim that the expired Internet-Draft became a finalized standard.

Node may produce unauthenticated plaintext during `decipher.update()`. The helper retains that exact buffer locally until `final()` authenticates the tag. Failure clears the retained plaintext and derived JavaScript key/nonce buffers before returning a fixed error. Availability is selected before processing: unsupported native builds use the existing noble cipher; native operation or authentication failures never trigger a second backend. The [Node 22.23.3 crypto documentation](https://nodejs.org/download/release/v22.23.3/docs/api/crypto.html) describes this ordering and the authentication requirement. Clearing these retained buffers does not guarantee erasure of copies internal to OpenSSL or the garbage collector.

The 24 new cases cover public AEAD/HChaCha vectors, byte-identical noble interoperability in both directions through the 4 MiB chunk limit, offset views, caller-buffer preservation, changed key/nonce/AAD/ciphertext/tag, truncation, appended bytes, real unauthenticated native-buffer clearing, derived-buffer clearing, no fallback after native failure, portable startup selection and invalid bounds/types. The separate reviewer read the final source, including the explicit plaintext lengths required by Node's TypeScript overloads.
