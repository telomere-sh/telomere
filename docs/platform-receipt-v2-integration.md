# Complete public Platform meter receipt: integration boundary

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

Integration update, 14 October: [opt-in CPU v2 issuance](platform-v2-issuance.md) now mounts the delegation, actual `/v2/leases` transport/host-response journal, terminal result/salt fence, public admission commitment, two-copy publisher, public retrieval and canonical financial settlement path. The default configuration remains v1. The sections below describe the earlier isolated design boundary; live independent storage, historical signing-time proof and public funded acceptance remain required. Legacy cores without `hostAdmission` preserve their original hash and expose `hostAdmissionVerified: false`.

The current public financial route verifies the onchain charge and refund. The presented-meter route verifies signatures on a caller-selected subset of HostKit ticks. Neither v1 receipt commits the complete signed tick/ACK sequence. A successful partial response must keep `completeTickHistoryVerified`, `billableSecondsVerifiedFromTicks` and `onchainTickCommitment` false. No v1 receipt may be relabeled v2.

The isolated `src/receipts/platform-v2.ts` module now constructs a canonical CPU-only evidence core from the original signed private lease, ordered signed tick/ACK pairs, exact quote signature, an EIP-712 controller delegation and a salted output commitment. It verifies both EOA signatures and every Ed25519 pair, including conservative ACK accounting, then hashes the entire redacted core into a versioned receipt hash. It requires EXITED for completed, STOPPED for cancelled/timed out, and EXITED or FAULT for failed; a signed tick has no exit code, so `executionStatusProven` remains false. The original argv, stdin, raw output and random salt are absent from the public core. It compares every quote field that `PlatformRunEscrow.getRun` stores, including leash, hardware class, region, image/workload hashes, price per second and inference price, with a historical-authority snapshot. It also compares `quoteExpiry`, which a future canonical reader must decode from the original `openRun` transaction because `getRun` does not retain it. The historical-authority input is **caller supplied**; this function does not authenticate an archive block or onchain receipt and returns `historicalAuthoritySource: "caller-supplied"`, `onchainReceiptVerified: false` and `independentlyPublished: false`.

`PlatformV2EvidenceJournal` is an opt-in, separately initialized private table. Its `record` method takes the full original private input and historical snapshot, recomputes the salt/output commitment and signatures, writes one core and salt per run, and rejects changed retries. A disk-reopen test covers exact replay and row-corruption detection. It is not mounted by `PlatformRuntimeService` or the default database migration. Database administrator access can still replace the table contents; this journal is a durable idempotency fence, **not** an independent immutable evidence publisher. The original output must remain in the private run journal to allow a future owner disclosure.

A separate [archive-backed opening reader](platform-v2-archive-opening.md) now derives historical authority from a confirmed canonical `openRun` transaction, its signed quote and reviewed historical chain state before invoking that core. The core's caller-supplied mode remains available for isolated tests. The opening result still sets `onchainReceiptVerified: false`. A further [combined reader](platform-v2-combined-verifier.md) also verifies the canonical settlement and financial root against the caller-presented core and is exposed through the configured server's [bounded read-only API](platform-v2-public-api.md). An [opt-in HostKit v2 admission route](host-v2-admission-envelope.md) signs and journals an exact-envelope receipt before runtime dispatch, but the existing core and combined reader do not commit or check that receipt. None of these modules issues a public v2 receipt, dates the delegation signature independently or publishes evidence copies.

The smallest safe v2 path is opt-in and CPU-only until it passes the following boundaries:

1. **Controller authority.** Use the EIP-712 `MeterDelegation` certificate signed by the Platform quote signer, binding chain ID, escrow and HostRegistry addresses, run ID, host ID and registered Ed25519 host key, controller Ed25519 key, the signed-lease hash, the unsigned-body meter-lease hash, validity interval and unique nonce. The implemented core includes the complete certificate, and the v2 receipt hash commits to it through the evidence-core digest. A public verifier must recover its EOA signer and compare it with `PlatformRunEscrow.quoteSigner()` at the canonical `RunOpened` block, check the signed open-run quote and the registry host key at that block, then recheck block hash and confirmation depth. A caller-provided controller key alone has no authority. Signer rotation, revocation and same-block upgrades require explicit policy review. The certificate cannot by itself prove when its EOA signature was produced; its v2 hash must be anchored by the settlement and receipt root.
2. **Immutable producer.** Add a default-off v2 receipt version to paid CPU runs. Persist a cryptographically random 32-byte output salt and the original signed lease/tick/ACK evidence before creating any settlement intent; on restart derive the identical receipt hash. The v2 preimage must bind the canonical quote, certificate hash, run/host scope, ordered pair-root and exact pair count, settlement time and conservative billable seconds, outcome status, and a salted output commitment. The salt and raw output stay private; a voluntary owner disclosure can later open that commitment. Keep the existing v1 path unchanged.
3. **Independent publication.** Before settlement, publish the canonical redacted **evidence core** by content digest to at least two independently readable immutable stores. The implemented core contains the certificate, quote and signature, ordered signed ticks and ACKs, output commitment and receipt-preimage fields, but no lease argv/stdin, raw output, output salt, receipt hash or later financial proof. The canonical open-transaction reference must be added to a separately checked retrieval manifest or to a reviewed core revision before production enablement. The v2 receipt hash commits to the evidence-core digest and exact pair-root; keeping the hash itself out of the core avoids a circular digest. Settlement transaction and financial proof references can be indexed alongside the immutable core after publication. A timeout or uncertain write must retain the original core and retry by the same digest; it must never substitute new evidence after a settlement is signed. Public `GET` retrieval must verify both stored copies against the digest and fail closed on missing or divergent evidence.
4. **Combined verifier.** Fetch the immutable package, verify its digest, canonical run-open and settlement transactions, published financial root and receipt hash, historical contract/asset pins, historical host and controller authority, every Ed25519 tick and ACK signature, pair ordering/hash links, terminal state and conservative billing bound. It may then report complete *committed* tick/ACK history and a signed-meter billing upper bound. It still cannot prove CPU computation, output correctness or TEE attestation. The private output can only be checked when its salt and bytes are voluntarily disclosed.

Acceptance needs local Anvil plus archive-state reads, real HostKit signatures, restart after each journal/publication step, omitted/reordered/forged pair rejection, signer rotation, revoked/mismatched certificate rejection, evidence-store divergence and canonical reorg rejection. A funded Base owner transaction, reviewed deployed pins and independent storage remain release gates.

Current isolated acceptance: `npx vitest run tests/platform-receipt-v2-core.test.ts` and `npm run typecheck`. The tests use generated EOA/Ed25519 keys and a disk-reopened private PGlite journal; they do not use an archive RPC, independent storage or public funds.
