# Read-only Platform v2 combined verifier

`verifyPlatformV2CombinedEvidence` is a read-only adapter for a caller-presented one-shot CPU v2 evidence core. The configured Platform server now exposes it through the [bounded v2 verification API](platform-v2-public-api.md). Given the original `openRun` and later settlement transaction hashes, it uses the reviewed Platform pins and archive RPC to combine three existing checks:

1. The canonical escrow settlement, receipt-root inclusion, charge and refund accounting from `PlatformPublicFinancialReader`.
2. Historical quote signer, HostRegistry host key, signed controller delegation and every ordered signed HostKit tick/ACK pair from `verifyPlatformV2OpeningEvidence`.
3. The original quote fields against the settled run at the canonical settlement block.

It requires the settled receipt hash, billed seconds, end time, price, payer and zero inference charge to match the evidence core. It repeats the financial proof after reading the opening block and rechecks both blocks for required confirmation depth. A timeout refund, v1 receipt hash, changed pair, inconsistent billing or reorg fails closed. The local Anvil/HostKit fixture in `tests/platform-v2-durable-bridge.test.ts` exercises an actual v2 hash published in a financial root and settled onchain, plus negative paths.

The positive verdict means that the **caller-presented** core matches an onchain receipt commitment and that the pairs **inside that committed core** are signed and ordered. It does not prove that every physical tick was recorded, when the delegation signature was issued, CPU computation or output correctness. It does not publish the core, make it independently retrievable, or turn the default v1 runtime into v2. The HTTP route has no paid write path. A trusted archive RPC and reviewed deployment pins remain inputs; this is not a light-client proof against a Byzantine RPC. Public v2 release still needs pre-settlement immutable publication in two independent stores, safe restart behavior, a mounted producer/retrieval path and funded-chain acceptance.
The current first HostKit tick and controller ACK bind the meter lease, not the delegation. Even a host-signed admission receipt would establish ordering only under a trusted HostKit unless an onchain or independently attested anchor is added. A separate post-opening commitment transaction is not a drop-in fix: the current lease/admission freshness window is about five seconds, shorter than a useful finality wait. A versioned workload-hash preimage committed by the existing signed quote, coupled with a HostKit-enforced v2 admission envelope, is a possible contract-preserving protocol change; it requires separate design and acceptance before any historical pre-admission claim.
