# Owner-signed Akash supplier binding (local M6 gate)

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

The private `SupplierService` can require an EIP-712 authorization before it records an Akash plan and again at activation. This gate is disabled unless `policy.requireSignedBinding` is `true`, reviewed `bindingPins` are configured, and a trusted private `signedBinding(owner, runId)` source is supplied. Neither the service nor this gate is mounted in the public controller. This change makes no paid Console request and produces no Telomere meter, settlement or refund.

The source supplies the original `PlatformQuote` and quote-signer signature plus an owner-signed `AkashSupplierIntent`. The intent signs the exact chain and escrow domain, owner and run ID, typed PlatformQuote digest, Akash account and deployment ID, order sequences, provider, manifest hash, `uact` bid price, bounded runtime hours, conservative blocks-per-hour assumption, projected maximum USDC reserve and a short expiry. `SupplierService.plan` checks the selected live bid and original manifest against that signature before committing the plan. It stores the intent digest in the durable journal. `activate` reloads and revalidates the same signed intent against the fresh authoritative run approval and exact pinned lease terms; a missing, expired or altered binding fails. A restart cannot silently downgrade a signed row to an unsigned policy.

Even a valid signed plan **cannot submit a paid lease** under this gate. Console's lease POST specifies provider and order but does not atomically specify a bid sequence (`bseq`) or maximum `uact` price. A fresh bid GET can race with a changed bid before POST. The code therefore returns `supplier_atomic_price_unavailable` after revalidation and before any durable pending transition or POST whenever `requireSignedBinding` is enabled. This is a signed planning and audit artifact, not pre-spend price enforcement. A later integration needs a provider operation with an atomic bid/price limit or a separately reviewed bounded spend mechanism before lifting this fence.

An optional read-only `AkashChainExactBidReader` narrows that uncertainty. It pins a reviewed HTTPS chain gateway and chain ID, then queries `/akash/market/v1beta5/bids/info` with the complete `{owner,dseq,gseq,oseq,provider,bseq}`. `SupplierService.activate` accepts exactly one matching current Console bid with `bseq`, rereads that precise chain bid, and rejects changed identity, state, denomination or price. It still returns `supplier_atomic_budget_unavailable` **before** a pending journal transition or paid POST if the unit-price preflight succeeds. A missing sequence, multiple matching bids, chain mismatch, malformed response or network error returns `supplier_exact_bid_unverified`. Without a configured chain reader the existing `supplier_atomic_price_unavailable` fence remains. This adapter makes only GET requests and is not mounted in the controller.

The direct-chain protocol explains both boundaries. The current [Akash `BidID` protobuf](https://github.com/akash-network/chain-sdk/blob/main/proto/node/akash/market/v1/bid.proto) includes `bseq`, and [`MsgCreateLease`](https://github.com/akash-network/chain-sdk/blob/main/proto/node/akash/market/v1beta5/leasemsg.proto) carries only that full `BidID`; the [market keeper](https://github.com/akash-network/node/blob/main/x/market/keeper/keeper.go) copies the selected bid's price into its lease. Thus a future signed direct-chain transaction could select one unit-priced bid rather than letting Console choose a different bid for the same provider. But `MsgCreateLease` has no runtime, total-spend, USDC, or refund field. The current deployment uses Console auto-top-up and an off-chain runtime limit. Neither the chain bid lookup nor the signed Telomere intent atomically limits the Akash lease's lifetime spend or converts `uact` to USDC. The read-only proof therefore reports `totalSpendBoundOnChain: false`; it is not permission to create a lease. The [Akash Console API](https://akash.network/docs/api-documentation/console-api/api-reference/) omits `bseq` and price from its lease POST, while the [chain query protobuf](https://github.com/akash-network/chain-sdk/blob/main/proto/node/akash/market/v1beta5/query.proto) defines the exact bid lookup used by the preflight.

On 2026-10-14 a read-only mainnet probe against Akash's [documented API endpoint](https://akash.network/docs/developers/deployment/cli/configuration/) confirmed that `GET /cosmos/base/tendermint/v1beta1/node_info` reported `akashnet-2` and `GET /akash/market/v1beta5/bids/info` accepted six `id.*` query fields, including `id.bseq=0`, and returned the exact bid. In a bounded 20-open-bid sample, all `bseq` values were `0`; nine bids used `uact`, nine an IBC denomination, and two `uakt`. Observed `uact` prices included fractional amounts such as `3.983040000000000000`. The read-only planner now accepts positive `uact` prices with at most 18 fractional places, compares equivalent chain and Console spellings as exact 10^-18 `uact` atoms, and stores the shortest exact decimal spelling in the journal and owner-signed intent. Existing integer journal and signature values retain the same bytes. The projected whole-`uact` hold is rounded upward only after multiplying the exact price by the maximum block count and inventory buffer; conversion to projected USDC is also rounded upward. Zero, excess precision, oversized values and non-`uact` denominations remain rejected. The `3.983040000000000000` fixture yields a 29,539 `uact` reserve for 7,200 blocks with a 3% buffer.

This local compatibility change does not cap the Akash lease's accrued lifetime liability, establish a trustworthy token/USDC exchange rate, or prove provider settlement. The signed path still returns `supplier_atomic_budget_unavailable` before any paid POST after an exact chain bid passes. This sample establishes the endpoint shape, not availability of a lease suitable for Telomere.

The `approvedRun` dependency must supply `quoteDigest` from the **actual admitted run's original quote** and verify the onchain run fields, including owner, run ID, host, class, image/region/workload hashes, duration and financial terms. The local verifier checks the quote-signer signature, owner signature, quote digest, CPU class, duration and a quote base amount at least as large as the projected supplier reserve. It cannot derive the original quote digest from `PlatformRunEscrow.getRun` alone because that contract does not store `quoteExpiry` or the quote signature. An untrusted callback could falsely claim admission, so production wiring must source it from a reviewed canonical quote journal plus onchain admission and archive evidence.

This gate does **not** change `PlatformRunEscrow`: its quote still names a HostRegistry `hostId`, and settlement still pays that host's `hostOperator`, not the Akash provider directly. Its quote does not commit the Akash tuple onchain. The separate signed intent is a controller-side authorization fence and audit artifact, not onchain enforcement or a supplier payment proof. The mounted paid runtime still caps quotes at 120 seconds, while a Console lease needs at least 3,600 seconds. Until a reviewed longer-lived Cell and full supplier accounting exist, keep lease creation disabled in the controller and treat this as a locally tested preflight gate only.

Focused validation: `tests/supplier-akash-signed-binding.test.ts` signs the quote and intent with independent local keys, checks provider, digest, spend, expiry and signer tampering, and proves that both an absent binding and a valid binding block lease POST without changing the durable planned row.
`tests/supplier-akash-exact-bid.test.ts` checks the complete query identity, pinned chain ID, price, denomination and read-only GET transport. The signed-binding service test also proves that a matching exact bid still blocks paid submission and that changed `bseq` or price does not reach the Console writer.
