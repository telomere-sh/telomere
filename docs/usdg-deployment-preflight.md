# Robinhood testnet USDG deployment preflight

Network update, 14 October 2026: the active implementation targets Base and native Circle USDC. Earlier Robinhood/USDG evidence below remains historical and does not prove Base deployment or funded acceptance. See [the current migration record](base-usdc-migration-2026-10-14.md).

Read-only RPC review on 2026-10-12 used the canonical Robinhood testnet block `133666836` (`0xeabd25353444b167061be6432f1b7ccacfe8b95989a4520190b0efbec87867fd`). The RPC endpoint was `https://rpc.testnet.chain.robinhood.com`. No public transaction was submitted. Raw probe evidence is retained privately in `.local/usdg-readonly-preflight-result.json` and `.local/usdg-eip1898-preflight-result.json`; the production profile has **not** been enabled. A later hash-based read of that same historical state returned RPC `-32000` (`historical state ... is not available`), so the public endpoint's usable state window is limited. A fork acceptance must select a fresh canonical block and recheck every pin before local writes. [Robinhood's connection guide](https://docs.robinhood.com/chain/connecting/) explicitly directs historical reads/indexing to an archive endpoint and says its public RPC is rate-limited and unsuitable for production. Delayed receipt inspection therefore needs a reviewed archive-capable RPC; it must never substitute the latest state for the historical receipt block.

The implemented facet checker subsequently passed on fresh canonical block `133724840` (`0x50d42282c73cb14a744b49d88cb9b484b4697120fcf7c3161dd06cf50f9a8022`): all three routes and facet code matched, while a deliberately wrong code hash failed. This was read-only and does not establish historical retention.

`getFacet(bytes4)` routed `transferWithAuthorization` (`0xe3ee160e`), `receiveWithAuthorization` (`0xef55bec6`), and `authorizationState` (`0xe94a0102`) to that facet at the reviewed block. These routes are mutable without a proxy bytecode or EIP-1967 implementation change. A Robinhood testnet USDG profile therefore requires the proxy, implementation, and authorization facet pins. The payment chain rechecks all three routes and the facet code at canonical history; the enabled profile checks the same before intake. Unrecognized routes or changed code fail closed.

Receipt inspection also checks parent-block routes and refuses receipt blocks containing proxy `FacetUpdate` or `Upgraded` events. [Paxos's reviewed implementation](https://github.com/paxosglobal/paxos-token-contracts/blob/674ac1046a0a40bfd2b6b892192998af9ac3b171/contracts/PaxosTokenClaimableRewards.sol#L544-L605) emits `FacetUpdate` through its normal admin route changes. Block-hash state reflects the end of a block, so these controls do not prove the exact delegatecall target if unreviewed code silently modifies route storage and restores it within one block. A strict guarantee against that administrator-level adversary requires transaction tracing or replay against a reviewed provider; otherwise public enablement must explicitly accept issuer-upgrade trust.

A read-only `eth_getLogs` probe with a block-hash filter and both event topics succeeded on fresh public block `133735125` (`0x45d366095721a006b051422fdc4859d8614d157eba18d01c92697d4f3fb503e6`); it returned zero matching logs. Private bounded evidence is in `.local/usdg-log-preflight-result.json`. This confirms the filter shape on a recent block, not historical log retention.

The token reported 6 decimals and `DOMAIN_SEPARATOR()` matched EIP-712 name `Global Dollar`, version `1`, chain ID `46630`, and the proxy address. Its `version()` call reverted with `FacetNotFound`; the reviewed EIP-712 value comes from the domain and contract source, not a working `version()` getter. `authorizationState` returned false for a sampled nonce. This does not prove future transfer policy or issuer state: refresh the pins and relevant policy checks before public enablement.

The public endpoint returned JSON-RPC `-32601` for `eth_getRawTransactionByHash` on a canonical successful type-2 transaction. The checked Node Vault-income reader has a bounded fallback for this exact unsupported-method code: it reconstructs the full signed EIP-1559 envelope from `eth_getTransactionByHash`, then checks the raw hash, recovered facilitator and exact Vault calldata before receipt inspection. Other RPC errors and transaction types fail closed. Adequate historical state retention and wallet-funded end-to-end acceptance remain release gates; a 2xx response or RPC `from` field alone is not settlement evidence. The [isolated USDG Vault acceptance](usdg-vault-fork-acceptance.md) now exercises the actual token bytecode and native Vault path without a user wallet; it does not replace public acceptance.

The optional main-server canonical USDG profile now refuses the public Robinhood RPC URL and probes historical state **before** enabling intake. The reviewed block `133666836` must be at least six hours behind the RPC's latest block and retain its exact canonical hash/timestamp, proxy code, EIP-1967 implementation slot/code, three facet routes/code, parent-block routes and block-hash-filtered `FacetUpdate`/`Upgraded` logs. All state reads use EIP-1898 block-hash context. `ROBINHOOD_ARCHIVE_RPC_URL=<private HTTPS endpoint> npm run preflight:usdg-archive` runs the same bounded read-only probe without loading a signing key and prints no endpoint or credentials. The main profile uses its configured `RPC_URL` for the same check. This is a historical capability check, not a guarantee of future retention, provider uptime or safety against silent intra-block issuer storage changes. A private archive provider still must be provisioned and pass this probe before public enablement.
