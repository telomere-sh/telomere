# Backend scope: NEAR inference, optional arbitrary GPU Cells

Network update, 14 October 2026: the active implementation targets Base and native Circle USDC. Earlier Robinhood/USDG evidence below remains historical and does not prove Base deployment or funded acceptance. See [the current migration record](base-usdc-migration-2026-10-14.md).

Decision recorded 13 October 2026. The required product is the Telomere backend; the 14 October target is Base with native Circle USDC. Frontend delivery is outside this backend scope. The owner has made arbitrary GPU Cells optional. The original M4 GPU-container rental, CUDA execution, GPU isolation/probes and GPU-second metering remain a separate future workstream, not a release gate for the revised backend.

Managed NEAR model inference is still required. An **inference-only logical Cell** accepts a bounded model request, validates the owner/agent authority, Leash, model and request policy, maximum input/output size, quote expiry and budget, persists an idempotent dispatch intent, submits at most one paid NEAR request, verifies current approved attestation and the response's binding to the request, and exposes only accepted output. It charges the fixed quoted inference amount only for an accepted result; unknown, late or invalid provider outcomes must be reconciled without automatic redispatch or unverified output. A sequence of calls requires per-call limits, durable accounting and explicit cumulative budget. No arbitrary code execution is implied.

The local controller can see plaintext model requests and responses unless an independently accepted confidential runtime protects them. A NEAR model attestation does not attest a Telomere CPU Cell, a caller-supplied Docker/CUDA image, filesystem/process isolation or an arbitrary Cyst-key recipient. Existing sealed-host and attestation-gated Cyst key-release requirements in M7 are unchanged by the M4 scope decision. A default-off, standalone [one-shot inference job](near-inference-only-runtime.md) is now implemented and locally tested without a CPU Host Kit lease. It has not passed a live paid Telomere request or public-chain settlement; current NEAR policy and Gateway admission remain blocked.

The revised mandatory milestone denominator is M1, M2, M3, M5, M6, M7, M8, M9 and M10. At the previous independent audit, the ten-stage midpoint was 64.85% and M4 stood at 7.5%. Removing only M4 yields `(648.5 - 7.5) / 9 = 71.22%` for **functional backend coverage**, with an engineering range of 67.0–75.4%. This is the scope-only baseline. A subsequent independent incremental review gives narrow credit to the locally accepted standalone inference path and Python SDK, producing a provisional **67.2–75.7%** range and **71.4%** midpoint, still approximately 71%. These pre-migration calculations establish neither live model-provider acceptance nor funded Base acceptance. Public release readiness is a separate gate and has no defensible percentage from this arithmetic.

Required release acceptance still includes a reviewed and funded Base wallet/contract path, current native USDC and archive-RPC pins, a real verified NEAR completion through the Telomere route, independent storage regions and host-loss recovery where the product claims them, supplier and sealed-key capabilities where advertised, production monitoring/restore drills, public receipt verification and the required independent contract audits. Features without their external acceptance stay disabled. The GPU CVM application can continue independently; it no longer blocks this revised backend release.
