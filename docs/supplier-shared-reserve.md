# Shared Akash and Nosana supplier reserve

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

Akash and Nosana admission now require one `FileSupplierSharedReserve` covering both exact local journals. It acquires one exclusive file lock before either journal commits a new reservation, reads both journals under that lock, and refuses another network's reservation for the same Telomere run or a combined projected USDC reserve above the configured ceiling. Each network still applies its own token inventory, run budget, identity and provider checks. If the shared lock survives a crash or either journal is corrupt/unreadable, admission fails closed. An idempotent retry can read its already committed reservation after an uncertain response.

Construct both services with the **same lock path, exact journal files and shared USDC ceiling**. Their constructors reject a shared gate wired to a different instance of their own journal. All supplier admission writers must use this gate. Only Akash `canceled_unsubmitted` rows, canceled before any lease POST, stop counting against the shared projected USDC ceiling; their run claims and idempotency tombstones remain. `closed_unsettled`, pending, active, and `quarantined` reservations keep their full projected reserve; an external closed status alone does not release treasury capacity. Operator recovery of a stale lock requires confirming the old writer has stopped and inspecting both journals. Editing or pruning journal records without an independently verified financial reconciliation is unsafe.

The shared ceiling is a conservative local admission control, not a token balance or chain-enforced spend limit. Separate processes configured with different lock paths or journal paths can still overcommit; deployment must pin one configuration and restrict file access. Neither supplier service is mounted in the main controller, and no approved-run callback, treasury inventory source, paid lease, signed in-cell meter, final provider accounting or refund exists in this slice. Nosana observes pre-existing jobs; Akash has separate default-off, single-attempt lease and deployment-close writers. Neither reports billable seconds. This is a component acceptance, not an operational supplier launch.

Validation: `tests/supplier-akash.test.ts`, `tests/supplier-nosana.test.ts` and `tests/supplier-shared-reserve.test.ts` exercise the existing per-network safeguards plus cross-network budget, duplicate-run, restart, concurrent lock, stale lock and corrupt peer journal cases. No external API request or payment is made by the shared-reserve test.
