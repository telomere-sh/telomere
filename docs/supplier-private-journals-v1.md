# Private supplier journals

This storage boundary does not enable a supplier endpoint, create a lease or establish external execution acceptance. Akash and Nosana keep their original version-1 financial records, reservation IDs, 128-record bounds and reserve rules. An Akash `canceled_unsubmitted` tombstone releases its local projected reserve; externally submitted, closed, unsettled and quarantined liabilities remain held.

For an explicitly reviewed **new installation**, construct `FileSupplierLedger`, `FileNosanaLedger` and `FileSupplierSharedReserve` using absolute private paths. Call `akash.initializeFresh()` and `nosana.initializeFresh()`, then `shared.initializeFresh()`. Ordinary `read()`, `transact()` and `admit()` never initialize storage. Calling `initializeFresh()` again refuses existing or half-created storage. There is no automatic legacy import or marker-repair path.

Each journal has its original JSON file, an immutable `<path>.initialized` identity marker with a random initialization generation, and an exclusive `<path>.lock` writer file. The shared gate retains its explicitly configured lock path and adds `<lockPath>.state` plus `<lockPath>.state.initialized`. Its marker binds both original journal paths and the exact shared reserve ceiling; its state pins both original peer initialization generations. Reinitializing a lost peer pair at the same path therefore cannot reuse retained shared authority. Changing paths, kinds, generations or that ceiling requires a separately reviewed migration; it is not a way to renew an exhausted reserve.

The private directory must be owned by the process user with POSIX mode 0700. Regular files are created with mode 0600; validation requires a single link, process-user ownership, owner read/write access and no group or world permissions. Symlinks and symlinked ancestors are refused. Windows operators must provision equivalent ACLs; the Linux directory-fsync guarantee is not claimed on Windows. Reads are bounded and compare named/opened identities, lengths and timestamps before and after reading. New JSON uses canonical `JSON.stringify` encoding; ambiguous duplicate keys are refused. Writes use a private exclusive temporary file, file fsync, original-state and writer-lock identity checks, atomic rename and mandatory Linux directory fsync.

A normal in-memory validation refusal preserves the original bytes. A shared local callback refusal releases its gate only when both journal contents can still be read and remain unchanged. A changed or unreadable callback outcome, or an uncertain write/durability outcome after mutation starts, leaves its writer lock held. There is no timeout, PID-age rule or automatic lock stealing. `read()` is an independent diagnostic of the currently present file; it does not resolve a held lock or prove final external accounting.

Before recovering a held lock, stop every writer and independently reconcile the exact original supplier identity, pending request, lifetime liability and retained records. Preserve the complete journal/marker/lock evidence. Restore only a reviewed complete durable state; never delete a marker or initialize an empty file to clear a liability. Existing unmarked journals require an explicit operator migration after this review; this batch intentionally supplies no automatic migration or import tool. A lost half-pair, interrupted initialization, or observed replaced path fails closed. Deleting or rolling back all journal/marker/shared anchors together is unsupported recovery and cannot be detected solely by those deleted local files; independently reviewed external inventory and accounting remain necessary.

All acceptance in the accompanying supplier tests is local filesystem/protocol-fixture acceptance. It establishes neither live Akash/Nosana execution, a funded external treasury, final supplier settlement nor fault-reserve accounting.
