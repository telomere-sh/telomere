# Large Cyst → CystRegistry publication plan

Current network target: Base 8453 / Base Sepolia 84532 with native USDC. Dated acceptance and linked JSON evidence retain their original network/source scope; see [migration record](base-usdc-migration-2026-10-14.md).

`LargeCystRegistryPlanner` connects an already committed encrypted multipart Cyst to the original Selection agent's `CystRegistry`. It remains an **internal, unsigned** backend boundary, now used by the bounded asynchronous agent-wallet route in [large-cyst-publication.md](large-cyst-publication.md). The controller has no signer or transaction submission. The agent wallet remains the only account that can execute the returned `commitChecked` calldata. The code does not need a Base owner wallet for local acceptance.

The planner requires a `LargeCystStore` with `isDurable(id)`. In the configured production path, only the pinned two-destination `LargeCystQuotaShadowStore` supplies that check. A local-only `LargeCystPrivateStore` cannot construct this planner. The planner reads the committed manifest, verifies both ciphertext copies including every part SHA-256, re-reads the same immutable manifest, and requires unchanged Selection binding and substantive CystRegistry state before returning a transaction. Both registry reads independently verify their canonical block; advancing to a new block with unchanged state is allowed. Missing, degraded, changed, or foreign-owned checkpoints fail closed. The confirmed registry reader checks chain ID, code hashes, contract relationships and historical canonical state.

The versioned `cystHash` is SHA-256 over `telomere.large-cyst.registry.v1\0` followed by the canonical JSON manifest. The manifest authenticates each ordered encrypted part through its SHA-256 digest; the two-copy durability check reads and verifies the actual bytes. This is deliberately a different commitment format from the small-Cyst ciphertext hash. `sizeBytes` includes the stored header, manifest, and all ciphertext parts and cannot exceed the CystRegistry's 2 GiB cap. `storageRef` is a Keccak-256 opaque locator bound to the checkpoint ID, owner, agent wallet, application schema, manifest SHA-256, and size. Neither a recovery key nor object-store credentials appear in the plan or onchain fields.

An internal controller can construct the planner only after initializing the reviewed two-destination store and the existing `RpcCystRegistryReader`:

```ts
const planner = new LargeCystRegistryPlanner(largeCysts, registryReader);
const plan = await planner.commitPlan(authenticatedAgentWallet, agentId, checkpointId);
// Return plan.transaction to the agent's independently checked wallet client.
// Do not sign or broadcast it in the controller.
```

The `verify(principal, agentId, checkpointId)` method accepts the registered owner or agent wallet, repeats the same storage and canonical-state checks, then compares the current live `CystRegistry` hash, size and locator. A concurrent commit increments the onchain revision and makes stale `commitChecked` calldata revert. A reorg that removes the publication makes verification false until the original agent publishes again.

The asynchronous route authenticates the original agent wallet, bounds admission and runs one remote durability audit at a time in the single-controller runtime. The scan reads every object in both destinations, so a large Cyst can consume several GiB of network I/O. The agent-side checked client must authenticate the original manifest with its recovery key before signing; the controller can validate stored part hashes but cannot validate the owner-keyed manifest MAC or prove the encrypted package is useful. A supplied, independently retained owner/agent key-wrap bundle is now included in the immutable manifest and thereby in the registry commitment. The original agent can fetch that manifest and digest-checked ciphertext parts through its signed session. The opaque locator still has no independent public resolver, and public Base wallet/storage acceptance remains open.

The route's durable queue, single audit worker, restart recovery, cancellation/deadline propagation and fresh canonical retrieval check are documented in [large-cyst-publication.md](large-cyst-publication.md). The existing owner-only large-file upload/download routes remain separate. The agent-side client independently authenticates the original manifest, reviewed deployment pins, current registry state and exact `from`/`to`/`value`/`data` before signing. Neither route nor planner signs a transaction. Independent-region and full-size operational acceptance remain outstanding.

`tests/large-cyst-registry.test.ts` uses real Anvil Selection/Vault/CystRegistry contracts, the canonical RPC reader, encrypted multipart files, a local quota shadow and two independent local directory stores. It verifies a zero-transaction unsigned plan, agent-signed `commitChecked`, owner verification, restore, real branch revert, stale revision rejection, foreign identity refusal, one-destination outage and corruption. It also mines a harmless new block during the durability scan and separately changes the actual registry revision; only the latter invalidates the plan. All four focused tests passed on Windows on 13 October 2026. These directories share one machine; they do not prove independent-region storage, public Base deployment, 2 GiB transfer speed or the under-20-second restore target.
