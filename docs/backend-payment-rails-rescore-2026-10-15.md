## Treasury limits within the accepted scope

The source verifier observes a reviewed Solana RPC's finalized transaction, exact classic-SPL USDC transfer, treasury ATA delta and original non-signer reference. The local fixture supplies those source observations; it is not a live Solana transfer or an independently verified consensus proof. Only the Base contracts, token movements, reorgs and classification are executed on an actual disposable local EVM in this acceptance. The supported public configuration is Solana mainnet/native USDC to Base mainnet/native USDC, with no mainnet-to-Sepolia substitution.

The service uses finite pre-existing Base treasury inventory. It does not mint USDC, bridge tokens, swap atomically across chains or rebalance network-token inventory. Its policy is bounded to one reviewed agent/Vault, at most 24 hours, 250 USDC per invoice, 2,500 USDC total issued credit and 128 retained invoices; tighter reviewed limits apply. Source identity, original authorization and signed transaction bytes survive retry. Expiry, refunds, new deposits and process restart do not replenish the original issuance budget. Ambiguous outcomes keep their holds.

Treasury authorization and relayer transaction signing require explicit external wallets. The server holds neither key. A source payment does not guarantee an immediately executable destination credit: unavailable inventory/capacity, unsupported source format, expired policy, changed appraisal/deployment, a replacement transaction or an ambiguous original authorization can require manual reconciliation. No automatic Solana refund is claimed. The historical Vault's `TransferWithAuthorization` wrapper can be front-run by relaying the token authorization directly into the intended Vault; this does not redirect funds, but skips classification. The implementation retains the source/hold and refuses a false credit or a second authorization. Preventing that workflow issue requires a separately reviewed `ReceiveWithAuthorization` Vault version.

The private journal is not rollback-proof storage or a complete part of the controller PostgreSQL backup. Preserve the reviewed profile, journal, creation marker and pending bytes. Operator-pinned private HTTPS RPCs are permitted; the feature does not claim DNS-pinned public-only RPC egress. Public funded Solana/Base transfers, real Base Account approval, treasury custody/recovery operation and the exact final whole-backend rollout remain separate acceptance gates.

The original full-regression/build/recovery gates, funded public Base acceptance when the wallet is supplied, verified public sources, independent escrow/registry audits, accepted provider appraisals and operational governance remain. This reassessment credits a bounded new permission-funded compute path and the focused treasury slice; it does not mark the backend complete or publicly launch-ready.
