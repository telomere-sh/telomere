# Isolated Robinhood USDG Vault-income acceptance

Network update, 14 October 2026: the active implementation targets Base and native Circle USDC. Earlier Robinhood/USDG evidence below remains historical and does not prove Base deployment or funded acceptance. See [the current migration record](base-usdc-migration-2026-10-14.md).

Historical entrypoint: `npm run acceptance:usdg-vault-fork` was used before the Base migration and is no longer active. Its source is archived below. The script selects a fresh Robinhood testnet block three blocks behind the observed head, pins its hash, and rechecks the USDG proxy, EIP-1967 implementation, authorization facet, three EIP-3009 routes, and EIP-712 domain through block-hash state reads. It starts a disposable Anvil fork on loopback, compiles and deploys the current platform contracts there, and uses generated fixture accounts. Its small `ForkOnlyIdentity` adapter supplies `ownerOf` on that disposable chain; this run does **not** establish integration with a canonical ERC-8004 identity registry.

An explicit upstream relay permits only read-only JSON-RPC methods and caps batches, calls, request bodies, response bodies, and runtime. All transaction and Anvil mutation calls go to the owned loopback process under `assertForkMutationTarget`. The fixture temporarily impersonates a public USDG holder **only inside the local fork** to fund generated accounts. It never submits a transaction to Robinhood or changes the application deployment profile. The script stops the child, relay, and temporary PGlite store on exit, writes a bounded private diagnostic log and a JSON result under `.local/usdg-vault-fork-*/`, and returns a nonzero exit status on failed acceptance or cleanup.

The first complete run on 2026-10-12 pinned block **133739969**, hash `0xf313f0c96a036d1e8753670dd3a5b74115c4b481676545c5a2465ec3c9cbd971`. Its private result is `.local/usdg-vault-fork-Cn30HW/result.json`, SHA-256 `b078e5616a94cbf710b4cc475b37dd68dea9e243560559d6356d40ede3c4a67f`.

The final tracked `npm` entrypoint repeated all five cases on fresh block **133742592**, hash `0x078fb2661f2d3719e7a6794818a9cb07678c88c62dd8eee9db4fdcf0fd3defe5`, with the same 156 public read-only calls, 30 guarded local mutations, and complete cleanup. The tracked script's SHA-256 is `415848d9c2f14817ca50f94cce21a3a786e39649704e6a3f072fe0b27aee4a17`. Strict TypeScript and the final Solidity/TypeScript/application build passed after the script's deadline-failure check was corrected. Both runs passed these cases:

| Case | Actual fork outcome |
| --- | --- |
| External payer | Signed USDG EIP-3009 deposited 1,000,001 units into the native Vault. The canonical receipt, Selection income event, token and Vault nonce, and balances agreed on a 10,001-unit fee and 990,000-unit net deposit. |
| Durable exact replay | After closing and reopening the disk journal, the same signed transaction bytes, hash, nonce, and attempt identity were retained; no second transfer occurred. |
| Owner subsidy | A 100,001-unit owner transfer reached the Vault with zero income fee and the subsidy counter increased by exactly that amount. |
| Wrong domain | A locally mined wrong-chain EIP-712 signature reverted atomically. No token nonce, Vault reference, balance, or income classification changed. |
| Token nonce front-run | A valid authorization reached USDG directly before the original Vault candidate. The candidate kept its own hash and durable bytes, required reconciliation, never adopted the other transaction, and credited no Selection income or fee. Exact retry did not broadcast again. |

The result recorded 156 public read-only RPC calls, 30 guarded local mutation requests, zero rejected relay methods, and confirmed closure of the child, relay, and store. Four `eth_getAccountInfo` calls returned public RPC `-32601` while Anvil fetched other state; acceptance remained valid. The executable script is [`scripts/usdg-vault-fork-acceptance.ts`](evidence/historical/usdg-vault-fork-acceptance-2026-10-13.ts.txt). Its private result and log are intentionally ignored by Git.

This is acceptance of the native Vault path against the reviewed **real USDG bytecode in an isolated fork**, not a public deployment or funded-wallet acceptance. The checked SDK fallback for public RPC `eth_getRawTransactionByHash` is covered separately by real HTTP tests and was not used in this run. Public enablement still requires an archive-capable historical RPC, current pin/policy refresh, an explicit issuer-upgrade trust decision or stronger intra-block tracing, the real identity registry path, funded operator accounts, and then the owner-wallet flow. See [`usdg-deployment-preflight.md`](usdg-deployment-preflight.md).
