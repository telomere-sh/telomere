# Agent restore of the current Cyst into a paid CPU Cell

`AgentCurrentCystPaidRestore` is an opt-in **agent-side Node adapter**. The original Selection agent signs into Telomere and separately pays/adopts a Vault CPU session. The adapter uses that agent session to resolve the *current* CystRegistry large-Cyst locator, unwraps the agent's X25519 recipient locally, restores up to **4,096 application-state bytes**, and sends one fixed restore command into that already admitted paid Cell. It never creates a reservation, signs a transaction, chooses an image or moves a running process.

The current Cyst can be up to 2 GiB in storage, but **this adapter rejects anything above 4,096 plaintext bytes before any part download**. The paid session's stdin is limited to 8 KiB, its scratch space to 16 MiB and its lifetime to 120 seconds. A general filesystem/archive restore needs a separately reviewed ingress protocol, image policy and longer-lived Cell.

Required client dependencies are `LargeCystAgentManifestStore` with the original agent's authenticated session, an independently pinned `RpcCystRegistryReader`, the agent's private X25519 `CystWrappingIdentity`, a checked `PlatformVaultRuntimeClient` with the same agent session and reviewed deployment/Vault pins, a private durable `CystCheckpointFileVault`, a private absolute temporary directory, and an immutable reviewed CPU image containing the exact `restoreArgvPrefix` program. The constructor also fixes owner, agent wallet, agent ID, application schema, image digest and paid-session command limit. The target must already be funded and admitted through the separate wallet flow.

`restore({targetRunId, restoreOperationId})` performs these checks:

1. Resolve the current locator through the signed agent HTTP route and a separate canonical CystRegistry reader. Reject a dead/frozen agent, different Selection owner/agent/Vault, wrong schema, unwrapped manifest or oversize state.
2. Check that the target's reviewed Vault binding, payer, host/image and signed session workload match the constructor's exact paid CPU image and command limit.
3. Restore the MAC/AEAD/integrity-checked ciphertext in a private temporary directory. Re-read the canonical registry after decryption and immediately before command dispatch; the descriptor, revision, owner/agent/Vault and same-height block hash must remain valid.
4. Durably encrypt and save the immutable operation binding before dispatch. It covers agent ID, original owner and wallet, Cyst descriptor and revision, observed source block, target Vault/run, state hash, reviewed image and command specification. The private journal scope is stable across application-schema changes for the same owner/agent/agent ID, so reusing an operation ID with a changed binding fails. The command ID is deterministic, and a lost response resends exactly the same command ID, argv and stdin; the Host Kit journal returns its original result rather than re-executing it.
5. Check the signed session command response's input hash and exact output receipt, then re-read the registry. A post-command chain change fails closed; it cannot roll back a guest side effect. Currentness is a point-in-time claim and must be rechecked before any later use that depends on it.

The guest restore program must validate every argv/stdin receipt field and the SHA-256/base64 state, durably apply the **same operation ID once**, and print only the receipt without state bytes. The client checks its exit status and receipt. The result proves command execution/output history, not semantic correctness of arbitrary guest restore code. The fixed argv prefix is bound in the private journal, while the separately reviewed image digest binds executable bytes in the paid quote. A later, deeper chain reorg that returns to the same descriptor and revision at a higher height cannot be distinguished from uninterrupted canonical history by the current latest-state reader; historical source-block verification needs an archive-capable reader. Currentness is therefore established only at each fresh canonical read.

**Confidentiality boundary:** the X25519 private identity and Cyst recovery key stay in the agent process. The plaintext state is deliberately sent as base64 in the paid command stdin and is persisted in the controller/Host Kit command journals; the reviewed operator can read it. Use only nonsecret application state until a separate in-Cell key-release design exists. The adapter clears its in-memory state buffer and removes the generated temporary directory after success or failure. A process crash can leave a private plaintext `.cyst-restore-*` or `state.bin` file under the configured temporary root; operator cleanup must inspect that root after crashes.

`tests/large-cyst-publication-main.test.ts` exercises the mounted Cyst route, two loopback S3 stores, original signed agent session and disposable Anvil CystRegistry publication. Its paid command endpoint is a strict replaying fixture that validates the transmitted state and writes a guest-state file once, including a deliberately lost response, changed-operation rejection, changed application schema and a same-height chain rollback. `tests/platform-paid-session.test.ts` separately exercises this adapter through the **real Vault-funded Platform controller, authenticated agent SDK, Host Kit journal and local-process paid Cell**, with a local encrypted Cyst file and real Anvil CystRegistry reader. That paid test uses a fixture locator instead of the signed Cyst HTTP route; the first test verifies the actual signed route. Together they cover both boundaries locally, but they are **not** a public-wallet/gVisor/independent-region deployment acceptance.
