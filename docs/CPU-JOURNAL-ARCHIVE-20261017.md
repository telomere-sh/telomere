# Retained financial journal archive, 17 October 2026

The backend removes the 2,000-settlement preparation limit through non-destructive archival. Every original signed transaction, nonce, job and receipt remains in PostgreSQL and encrypted backups. Archive membership has a partial index; original bytes are never deleted or rewritten. Disk capacity and the existing backup-size bounds still apply.

Each archive batch links to the preceding checkpoint and commits its original rows' fingerprints, cumulative row count, chain/escrow/token/signer scope, nonce floor and canonical finalized block. The operator signs metadata in a separate `TelomereJournalArchive` EIP-712 domain. This operation sends no EVM transaction and spends no ETH or USDC. The checkpoint and row markers commit in one SQL transaction, with immutable-history triggers. Only finalized terminal jobs whose transaction, saved receipt, event, contract terms and charge/refund agree can enter the archive. Pending and disputed rows remain active.

Before creating another settlement, the bridge serializes nonce selection with a PostgreSQL lock, verifies archive integrity and the canonical anchor/nonce floor, and checks every active journal in bounded pages. Startup walks all retained archive batches. Later calls verify new batches and recheck the canonical head. Existing requests retain their original transaction/hash. Missing archived receipts, a changed finalized anchor or a regressed nonce stop the operation before another broadcast.

## Actual local-chain acceptance

The final acceptance mined **2,105 distinct settlements** on loopback chain 31337 with generated accounts and a distinct treasury. These historical records carry synthetic metering fixtures; they are not a claim of 2,105 CPU executions. All 2,105 local token transfers were real contract executions. Creating this history took 81.084 seconds.

The test killed a separate archive process with SIGKILL while PostgreSQL was inside an uncommitted membership update. No partial checkpoint or marker survived; every original transaction remained. It then archived the history in **nine batches**, reopened storage with a fresh bridge, verified all original bytes and replayed the oldest/newest hashes without increasing the signer nonce. Archive/reopen/replay took 11.134 seconds.

After that history, one genuine gVisor CPU job settled at nonce **2105**, charged **400 atomic test tokens** and returned **1,600** from a 2,000 reserve. The test restored a dump captured after the new signed journal was durable but before broadcast, while its transaction had subsequently mined. Recovery returned the identical original raw bytes/hash and anchored receipt, with exactly one CPU execution and no additional signer nonce. Independent treasury and available balance conserved all one million funded atomic test tokens.

An unavailable archived receipt caused zero broadcasts. Reverting the actual local chain and replacing the blocks containing its archived finalized anchor also caused zero broadcasts. Separate unit checks cover corrupt restored bytes, invalid checkpoint signatures, concurrent same-run requests, immutable-history SQL, nonce regression, an unresolved nonce beyond the first two pages and more than 2,000 active rows while finality is delayed.

Three preliminary harness attempts are retained. The first was stopped before completion while receipt polling and the final candidate were updated. The next exceeded its 2 GiB cgroup because Anvil retained historical state snapshots. Anvil now retains 16 state snapshots and all 8,192 permitted transaction blocks/receipts; its measured peak RSS was 220,216 KiB. A subsequent attempt correctly stopped when the final historical transactions had not yet reached Anvil's finalized marker. The final harness explicitly mines and checks finality before archiving them. Production data and the independently running twelve-hour soak were unaffected by these attempts.
