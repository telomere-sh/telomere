## Critical compatibility and acceptance gaps

1. **Two incompatible financial paths.** `src/bridge.ts`, worker, SDKs and AgentVault use `TelomereRunEscrow`. The new `PlatformRunEscrow` has different quote/Leash/settlement contracts. Its full settlement leaf binds financial run fields; current hourly receipts use `double-keccak-receipt-v1`, a receipt-hash-only leaf. The roots cannot be interchanged. A live bridge must construct the platform quote and full leaf, publish before proof-based settlement, and migrate/adapt the Vault and clients. New contract tests prove those components in isolation; they do not establish this integration.
2. **Generic compute is absent from the product path.** Existing owner job APIs run four bounded CPU algorithms for up to 120 seconds. HostKit admits bounded argv in an allowlisted image, but its controller adapter currently invokes the fixed task runner. There is no full `cell.exec` session/container service, GPU rental or external supplier market. The new interruptible application coordinator exercises real continuation but does not fill these generic-runtime gaps.
3. **Lifecycle still needs a real product runner.** The client protocol and encrypted application continuation are real. Resource profile enforcement, consistent filesystem capture, fencing in-flight operations, key-vault persistence and approved replacement capacity remain runner obligations. The 30-minute roll-ahead policy versus the current two-minute CPU jobs is unsuitable as a long-lived lease implementation. Application processes in acceptance are not separate attested hosts.
4. **TEE verification and key release are different requirements.** The existing NEAR inference protocol does not create a Telomere sealed host or release checkpoint keys to one. An attested provider signer is not complete proof of same-instance model/Gateway/response binding. Gateway OutOfDate and expired/unapproved workload policy remain real blockers.
5. **Financial/public controls require consolidation.** The new contracts do not establish all original pre-audit platform ceilings: $250/run, $1,000/day Leash, $2,500 Selection vault, $500,000 total escrow and $25,000 considered host collateral. Selection's $20/hour and $200/day are separate controls. Governance addresses alone do not deploy a 3/5 Safe, guardian 2/3 or 48-hour timelock. Token recipients are not proof of stake-reward distribution or an actual market buy-and-burn.
6. **Income is currently onchain classified funding.** Known owner/agent/family/platform sources are excluded by the contracts, which is useful and tested. That does not independently prove that remaining payments came from declared commercial services, prevent arbitrary intermediary funding or implement verified endpoint ownership. Public metrics must describe their precise onchain evidence.
7. **Storage review labels do not establish independent failure domains.** Two endpoints on one VPS can validate S3/replication behavior but cannot satisfy the original two-region resilience requirement. Current encrypted application size is 2 MiB; no inference about a 2 GB restore in less than 20 seconds is justified.
